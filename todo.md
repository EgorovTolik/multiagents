## Серверная система маршрутизации (routing config)

**Контекст:** Локальная модель (Qwen 35B) не следует промпт-инструкциям по условной маршрутизации. Оркестратор всегда передаёт код-задачи напрямую на code-worker, игнорируя правило "сначала feature-planner". Prompt engineering исчерпан.

**Идея:** Файл конфигурации (например `routing.json` в корне или `system/routing.json`) с декларативными правилами маршрутизации:
- Условия (ключевые слова, типы задач)
- Цепочки (orchestrator → planner → worker → reviewer)
- Приоритеты

**Сложность:** Агенты динамические (создаются/удаляются), поэтому правила не могут быть жёстко закодированы. Нужна система, которая:
1. Читает конфигурацию при старте
2. Обновляется при создании/удалении агентов
3. Применяется на сервере (в runner.ts) при маршрутизации

**Статус:** Не начато. Требует проектирования.
