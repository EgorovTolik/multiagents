# Оценка объёма работ

## Шкала сложности

| Уровень | Описание | Типичные задачи |
|---------|----------|----------------|
| Низкая | Простая задача, знакомый паттерн | Багфикс, небольшой UI-элемент, документация |
| Средняя | Требует изучения, несколько компонентов | Новая фича в известном модуле, интеграция |
| Высокая | Новое решение, много компонентов, неопределённость | Архитектурное изменение, новый модуль, интеграция с внешней системой |

## Шкала объёма

| Уровень | Ориентировочно | Описание |
|---------|---------------|---------|
| Маленький | 1-4 часа | Небольшое изменение, 1-2 файла |
| Средний | 0.5-1 день | Логический модуль, 3-5 файлов |
| Большой | 1-2 дня | Комплексная фича, 5+ файлов, требует ревью |

## Методики оценки

### 1. Аналогия
Сравни с похожими задачами из прошлого опыта.
> "Это похоже на задачу X, которая заняла 2 дня"

### 2. Декомпозиция до атомов
Если не можешь оценить — разбей на части и оцени каждую.

### 3. Буфер неопределённости
- Низкая неопределённость: +10% к оценке
- Средняя неопределённость: +25% к оценке
- Высокая неопределённость: +50% к оценке

### 4. Three-point estimation (для сложных задач)
- Optimistic (O) — всё пойдёт хорошо
- Most likely (M) — реалистичный сценарий
- Pessimistic (P) — будут проблемы
- **Expected = (O + 4M + P) / 6**

## Типичные заблуждения

⚠️ **Planning fallacy:** Всегда закладывай буфер. Реальные сроки = оценка × 1.5-2.

⚠️ **Не забывай про:**
- Code review (1-2 дня ожидания)
- Итерации по фидбеку (+30% к времени)
- Тестирование (минимум 20-30% от времени реализации)
- Деплой и мониторинг (+10-15%)
- Коммуникация и стендапы

## Формат оценки

```
Оценка этапа:
- Сложность: [низкая/средняя/высокая]
- Объём: [маленький/средний/большой]
- Уверенность: [высокая/средняя/низкая]
- Обоснование: [почему такая оценка]
- Буфер: [X% на неопределённость]
```
