# Анализ зависимостей

## Типы зависимостей

| Тип | Описание | Пример |
|-----|----------|--------|
| Логическая (hard) | Один этап физически не может начаться без другого | Бэкенд-API → Фронтенд-интеграция |
| Ресурсная (soft) | Ограничение по ресурсам | Один разработчик на два этапа |
| Приоритетная | Бизнес-приоритет | Сначала критичный функционал |

## Метод анализа

### Шаг 1: Идентификация
Для каждого этапа спроси:
- Какие данные/результаты нужны для начала?
- Какие другие этапы создают эти данные?
- Есть ли общие ресурсы (компоненты, API, БД)?

### Шаг 2: Построение графа
- Нарисуй DAG (Directed Acyclic Graph) этапов
- Найди критический путь (самую длинную последовательность зависимых этапов)
- Определи параллельно-выполнимые ветки

### Шаг 3: Валидация
- Нет ли циклических зависимостей?
- Можно ли уменьшить зависимости через абстракции?
- Есть ли узкие места (один разработчик на много зависимых этапов)?

### Шаг 4: Оптимизация
- Можно ли мокать зависимости для параллельной работы?
- Можно ли вынести общие зависимости в отдельный этап?
- Стоит ли переупорядочить этапы для лучшей параллелизации?

## Формат описания зависимостей

```
Этап X → зависит от: Этап Y, Этап Z
  Y: [тип зависимости] — [почему]
  Z: [тип зависимости] — [почему]

Этап A → может параллельно с: Этап B
  Причина: [нет общих ресурсов, разные модули]
```

## Признаки проблемных зависимостей

🚩 **Требует внимания:**
- Этап зависит от 3+ других этапов → риск блокировки
- Циклическая зависимость → ошибка в планировании
- Критический путь > 60% общего времени → риск срыва сроков
- Один разработчик на 2+ последовательных этапа → узкое место
