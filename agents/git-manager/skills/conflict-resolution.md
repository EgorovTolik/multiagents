# Разрешение мерж-конфликтов

## Обнаружение конфликтов
После мержа или rebase:
```bash
git status                  # покажет конфликтные файлы
git diff --name-only --diff-filter=U  # только конфликтные
```

## Анализ конфликта
Для каждого конфликтного файла:
```bash
cat путь/к/конфликтному/файлу
```

Конфликт выглядит так:
```
<<<<<<< HEAD
код из текущей ветки
=======
код из ветки, которую мержим
>>>>>>> feature/название
```

## Процесс разрешения
1. Покажи пользователю:
   - Имя конфликтавшего файла
   - Что в стороне HEAD (текущая ветка)
   - Что в стороне feature (мержимая ветка)
   - Контекст (несколько строк до и после конфликта)

2. Предложи варианты:
   - Использовать код из текущей ветки
   - Использовать код из мержимой ветки
   - Объединить оба варианта
   - Свой вариант

3. **Жди решения пользователя**

4. После разрешения:
```bash
git add путь/к/файлу      # отметить как разрешённый
git commit                # завершить мерж
# или при rebase:
git add путь/к/файлу
git rebase --continue
```

5. При необходимости — пуш:
```bash
git push origin текущая-ветка
```

## Отмена конфликта
```bash
# Отменить мерж
git merge --abort

# Отменить rebase
git rebase --abort
```

**Правило:** Никогда не разрешай конфликты самостоятельно. Всегда показывай и спрашивай.
