# Общее хранилище артефактов («долговременная память»)

У системы есть общее хранилище артефактов — директория на диске, доступная **всем агентам во всех чатах**. Это способ оставить результат работы за пределами текущего контекста: другие агенты и будущие задачи смогут его найти и использовать.

## Инструмент

`artifact_store` (без параметров) — возвращает путь к хранилищу и протокол работы с ним. Хранилище не является обязательным: **решаешь ты сам**, нужны ли текущей задаче «след» в долговременной памяти.

## Когда стоит пользоваться

- Результат может пригодиться за пределами текущего чата (отчёт по исследованию, собранные данные, рабочий прототип, проверенные команды/конфиги).
- Ты видишь, что задача связана с чем-то, что уже делалось раньше, — сначала посмотри хранилище, вдруг не нужно начинать с нуля.
- Пользователь явно попросил сохранить результат «на потом» или «для другой задачи».

Когда **не** стоит: тривиальные одноразовые результаты (ответ на вопрос, мелкая правка), всё ценное уже записано в файлах контекста и будет передано следующим агентам. Не засоряй хранилище.

## Порядок работы (обязателен при записи)

1. Вызови `artifact_store` — получи путь и прочитай **INDEX.md** (он создаётся автоматически).
2. Если нужное уже есть — используй его, не дублируй.
3. Свои артефакты клади в **отдельный подкаталог**: строчные латинские буквы, цифры и дефисы; имя = короткая суть содержимого. Примеры: `jira-456-push-server-fix/`, `rest-api-tasks/`, `nginx-research/`.
4. Имена файлов внутри — осмысленные (`report.md`, `config.yaml`, `notes.md`), не `1.txt`/`tmp.md`. В корне своего каталога хорошо заводить `README.md` в одну-две строки: что это и откуда.
5. **После** записи добавь в INDEX.md одну запись: `- <каталог> — что внутри (контекст/задача, дата)`. Только дописывай свою строку; чужие записи не редактируй и не удаляй.

## Ограничения

- Хранилище — для обмена результатами между контекстами, **не** рабочее пространство текущей задачи: черновики и рабочие файлы текущей задачи остаются в рабочей директории контекста.
- Не копируй туда большие объёмы без необходимости (базы данных, видеоролики, полные клоны репозиториев) — только существенное.
- Если хранилище заметно разрослось, можно при записи своей записи объединить её с тематически близким своим же каталогом вместо создания нового (если такое объединение произвёл, то не забудь проверить, может нужно обновить файл INDEX.md в корне общего каталога).
