# Файлы заданий и результатов (handoff protocol)

## ГЛАВНОЕ ПРАВИЛО

При передаче задачи другому агенту ты **ОБЯЗАН** сначала вызвать инструмент `handoff_file` для создания файла с полным техническим заданием. В параметр `context` инструмента `route_to_agent` передаёшь только **короткое описание** (1–3 предложения) и **абсолютный путь к файлу ТЗ**, который вернул `handoff_file`.

## Инструмент handoff_file

У тебя есть инструмент `handoff_file` — он создаёт файл задания или результата с автоматическим timestamp-именем. Тебе НЕ нужно самому думать об имени файла или создавать директорию — инструмент делает всё сам.

### Параметры
| Параметр | Описание |
|----------|----------|
| `type` | `"task"` (файл задания) или `"result"` (файл с результатом) |
| `title` | Краткое название: 1–5 слов |
| `body` | Полное содержимое в markdown |

### Пример вызова — создание задания:
```
handoff_file(
  type: "task",
  title: "Создать REST API задач",
  body: "## Контекст\nПользователь хочет CRUD API для управления задачами.\n\n## Задача\nСоздай Express-приложение с эндпоинтами GET/POST/PUT/DELETE /tasks...\n\n## Файлы для работы\n(нет)\n\n## Результат\nЗапиши в result-файл (путь получишь от handoff_file type=result)"
)
```

### Пример вызова — запись результата:
```
handoff_file(
  type: "result",
  title: "REST API задач создан",
  body: "## Сделано\nСоздан Express-сервер с CRUD /tasks.\n\n## Детали\nФайлы: app.js, package.json. Тесты пройдены...\n\n## Файлы\n/abs/path/app.js — основной сервер"
)
```

### Возвращаемое значение
Инструмент возвращает **абсолютный путь** к созданному файлу. Используй этот путь:
- В `context` при `route_to_agent`
- В сообщении пользователю (система превратит путь в ссылку для скачивания)

## Структура файлов

Файлы автоматически создаются в поддиректориях контекста:
```
<рабочая директория>/
  tasks/           ← task-<timestamp>.md
  results/         ← result-<timestamp>.md
```

Имя файла: `task-1752304875000.md` / `result-1752304900000.md` (unix ms).
Timestamp позволяет отслеживать хронологию и отлаживать цепочки.

## Что писать в параметрах route_to_agent

### `reason` (для пользователя в UI — одно короткое предложение):
```
Создать REST API для задач
```

### `context` (для целевого агента — короткое описание + путь к ТЗ):
```
Задача: создать REST API для управления задачами. Полное ТЗ: /abs/path/contexts/abc/tasks/task-1752304875000.md
Прочитай файл перед началом работы. Результат запиши через handoff_file (type=result).
```

## Цепочки агентов

Если ты (специалист) передаёшь работу следующему агенту:
1. Вызови `handoff_file(type="task", ...)` — получи путь к ТЗ
2. В `route_to_agent.context` укажи короткое описание + этот путь
3. Если нужно сослаться на предыдущие артефакты — добавь их пути в body задания

**Пример цепочки:**
- Оркестратор → Кодер: handoff_file(task) → route_to_agent с путём к task-<ts>.md
- Кодер работает → handoff_file(result) → пишет result-<ts>.md
- Кодер → Ревьюер: handoff_file(task, ссылается на result-<ts>.md) → route_to_agent

## ВАЖНО

- **Всегда** вызывай `handoff_file(type="task", ...)` ПЕРЕД `route_to_agent` — без исключения.
- **Всегда** вызывай `handoff_file(type="result", ...)` при завершении работы — даже если ответ короткий.
- В сообщении пользователю упоминай файлы полным абсолютным путём (система превратит их в ссылки).
- Не пересказывай содержимое файлов в `context` — только краткая сводка и путь. Агент сам прочитает файл.
- Если задание простое — всё равно используй `handoff_file` (единый формат, единая история).
